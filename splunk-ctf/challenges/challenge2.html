🔍 The Failed Login Mystery

EASY 150 POINTS ~25 MIN

Detect brute force attacks by analyzing Windows authentication logs.

📚CONCEPTS TO LEARN

Brute Force Attacks

A brute force attack is when an attacker systematically tries many passwords or usernames until finding the correct one. In logs, this appears as multiple failed login attempts followed by a success (or continuous failures).

  • Password Spraying: Few passwords against many accounts
  • Credential Stuffing: Known username/password pairs
  • Dictionary Attack: Common passwords against single account

Windows Security Event IDs

Event IDDescriptionSignificance
4624Successful logonUser authenticated successfully
4625Failed logonAuthentication failure - key for brute force
4648Explicit credential logonRunAs or network logon with creds
4672Special privileges assignedAdmin/elevated logon
4776NTLM authenticationDomain controller validation

The stats Command Deep Dive

The stats command is essential for aggregating data:

SPL
| stats count as attempts, 
        dc(user) as unique_users, 
        values(user) as usernames,
        earliest(_time) as first_attempt,
        latest(_time) as last_attempt
  by src_ip
  • count - Total number of events
  • dc(field) - Distinct count of unique values
  • values(field) - List all unique values
  • earliest/latest(_time) - Time boundaries

Detecting Brute Force with SPL

Look for: High failure count from single IP, attempts across multiple accounts, rapid succession of attempts.

SPL
index=windows EventCode=4625
| stats count by src_ip, user
| where count > 5
| sort -count

🎯THE CHALLENGE

SITUATION: Multiple users reported being locked out of their accounts this morning. Security logs show a spike in authentication failures. Analyze the Windows Security logs to identify the attacker's IP address and the username they successfully compromised after the brute force.


Find: (1) The attacker's source IP, (2) The account they compromised (had 4625 failures then 4624 success).

FLAG FORMAT
FLAG{IP_USERNAME}
📥 Download Challenge Data
💡 HINT

Look for an IP with many 4625 events followed by a 4624 for the same user. Use transaction or correlate by time.

🔓SOLUTION

Find IPs with Most Failed Logins

SPL
index=windows EventCode=4625
| stats count as failures by src_ip
| sort -failures

This reveals 10.20.30.99 has 847 failed attempts - clearly suspicious!

Check Which Users Were Targeted

SPL
index=windows EventCode=4625 src_ip="10.20.30.99"
| stats count by user
| sort -count

Find Successful Login After Failures

SPL
index=windows (EventCode=4624 OR EventCode=4625) src_ip="10.20.30.99"
| stats count(eval(EventCode=4625)) as failures,
        count(eval(EventCode=4624)) as successes
  by user
| where failures > 0 AND successes > 0

This shows user "svc_backup" had failures then a successful login!

Confirm Timeline

SPL
index=windows (EventCode=4624 OR EventCode=4625) src_ip="10.20.30.99" user="svc_backup"
| sort _time
| table _time, EventCode, user, src_ip
🚩 THE FLAG
FLAG{10.20.30.99_svc_backup}
