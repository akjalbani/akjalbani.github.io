🔐 Credential Theft

HARD 450 POINTS ~60 MIN T1003

Detect LSASS memory dumping and credential access attempts.

📚CONCEPTS TO LEARN

LSASS and Credential Storage

The Local Security Authority Subsystem Service (lsass.exe) handles Windows authentication. It stores credentials in memory, making it a prime target for attackers.

  • NTLM hashes: Used for pass-the-hash attacks
  • Kerberos tickets: Used for pass-the-ticket attacks
  • Plaintext passwords: Sometimes cached in memory

Sysmon Event ID 10 - Process Access

Sysmon Event ID 10 logs when a process accesses another process's memory. Critical for LSASS monitoring!

SPL
index=sysmon EventCode=10 TargetImage="*lsass.exe"
| eval access_rights=case(
    GrantedAccess="0x1010", "PROCESS_QUERY_LIMITED_INFO + PROCESS_VM_READ",
    GrantedAccess="0x1fffff", "PROCESS_ALL_ACCESS",
    GrantedAccess="0x1410", "Memory Read Access"
)
| stats count by SourceImage, access_rights

Known Dumping Tools

  • mimikatz.exe: Classic credential dumper
  • procdump.exe: Microsoft Sysinternals (abused)
  • comsvcs.dll: MiniDump via rundll32
  • Task Manager: Create dump file feature
  • Out-Minidump: PowerShell method

🎯THE CHALLENGE

SITUATION: Your Sysmon deployment detected suspicious access to lsass.exe. An attacker may have dumped credentials. Analyze the logs to find:


1. The tool/process used to access LSASS
2. The user account that executed it
3. The hostname where this occurred

FLAG FORMAT
FLAG{PROCESS_USER_HOST}
📥 Download Challenge Data
💡 HINT

Look for Sysmon Event ID 10 where TargetImage is lsass.exe. Focus on unusual SourceImage processes and suspicious GrantedAccess values (0x1fffff = FULL_ACCESS).

🔓SOLUTION

Find All LSASS Access Events

SPL
index=sysmon EventCode=10 TargetImage="*lsass.exe"
| stats count by SourceImage, GrantedAccess
| sort -count

Most access is from legitimate Windows processes. Look for anomalies!

Filter for Suspicious Access Rights

SPL
index=sysmon EventCode=10 TargetImage="*lsass.exe"
| where GrantedAccess="0x1fffff" OR GrantedAccess="0x1010" OR GrantedAccess="0x1410"
| stats count by SourceImage, GrantedAccess, User, host

rundll32.exe accessing LSASS with 0x1fffff? That's credential dumping!

Investigate the Suspicious Process

SPL
index=sysmon EventCode=10 SourceImage="*rundll32.exe" TargetImage="*lsass.exe"
| table _time, host, User, SourceImage, GrantedAccess, CallTrace

The CallTrace shows comsvcs.dll - this is the MiniDump technique!

Correlate with Process Creation

SPL
index=sysmon EventCode=1 Image="*rundll32.exe" CommandLine="*comsvcs*MiniDump*"
| table _time, host, User, CommandLine, ParentImage

Confirms: rundll32.exe comsvcs.dll MiniDump [LSASS_PID] - run by CORP\jsmith on SRV-FILE01

🚩 THE FLAG
FLAG{rundll32.exe_CORP\jsmith_SRV-FILE01}
⚠️ DETECTION TIP

Create alerts for: ANY non-Windows process accessing lsass.exe, GrantedAccess 0x1fffff to lsass.exe, and rundll32.exe with comsvcs.dll in CommandLine.
