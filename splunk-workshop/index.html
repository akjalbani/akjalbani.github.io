01

Introduction

Welcome to the Teaching Splunk: A Train-the-Trainer Workshop.

Splunk is a platform that collects machine data, stores it, and lets you search it. In this workshop, machine data means simple log files from a web server, a practice login page, and basic Linux login records.

What learners will build

Learners will create two EC2 instances. One instance runs Splunk Enterprise. The second instance runs Apache and the Splunk Universal Forwarder. The forwarder sends log files to Splunk so learners can search and visualise them.

1. Web server Learners visit simple pages such as /, /about.html, /resources.html, and /login.php?user=teacher.
2. Log files Apache writes page visits to /var/log/apache2/access.log. The practice login page writes safe user activity to /var/log/simple-login.log. The Splunk Enterprise VM also monitors its own /var/log/auth.log.
3. Universal Forwarder The forwarder reads web server files and sends events to the Splunk server on port 9997.
4. Splunk Enterprise Splunk receives, indexes, searches, and displays the log data, including its own local Linux login activity.

Step 4 — Install Splunk Enterprise

Copy your Splunk Enterprise Linux .deb download URL from your Splunk account. Then run the script below on the Splunk server.

bash — create and run the install script
nano splunk-install.sh
# Paste the script below. Save with Ctrl+O, Enter, then Ctrl+X.
chmod +x splunk-install.sh
./splunk-install.sh
bash — splunk-install.sh
#!/bin/bash
set -e

# Paste your Splunk Enterprise .deb download URL from splunk.com below.
SPLUNK_DEB_URL="PASTE-YOUR-SPLUNK-ENTERPRISE-DEB-URL-HERE"
ADMIN_PASS="Workshop2026!"
SPLUNK_HOME="/opt/splunk"

sudo apt-get update -y
sudo apt-get install -y wget curl net-tools rsyslog

wget -O /tmp/splunk-enterprise.deb "$SPLUNK_DEB_URL"
sudo dpkg -i /tmp/splunk-enterprise.deb

sudo $SPLUNK_HOME/bin/splunk start \
  --accept-license --answer-yes --no-prompt \
  --run-as-root \
  --seed-passwd "$ADMIN_PASS"

sudo $SPLUNK_HOME/bin/splunk enable boot-start \
  --accept-license --answer-yes --no-prompt \
  --run-as-root

sudo $SPLUNK_HOME/bin/splunk enable listen 9997 \
  --run-as-root \
  -auth admin:"$ADMIN_PASS"

sudo $SPLUNK_HOME/bin/splunk add index webserverlogs \
  --run-as-root \
  -auth admin:"$ADMIN_PASS"

sudo $SPLUNK_HOME/bin/splunk add index securitylogs \
  --run-as-root \
  -auth admin:"$ADMIN_PASS"

# Enable and prepare Linux auth logging on the Splunk Enterprise VM.
sudo systemctl enable --now rsyslog
sudo touch /var/log/auth.log
sudo chown root:adm /var/log/auth.log
sudo chmod 640 /var/log/auth.log

# Monitor the Splunk Enterprise VM's own login-related Linux log.
sudo $SPLUNK_HOME/bin/splunk add monitor /var/log/auth.log \
  -index securitylogs \
  -sourcetype linux_secure \
  --run-as-root \
  -auth admin:"$ADMIN_PASS"

echo "Splunk Enterprise is ready."
echo "Open: http://YOUR-SPLUNK-SERVER-PUBLIC-IP:8000"
echo "Username: admin"
echo "Password: $ADMIN_PASS"
Expected result

Open http://YOUR-SPLUNK-SERVER-PUBLIC-IP:8000. Log in with username admin and the workshop password shown in the script.

Record this value

In the EC2 details page for the Splunk server, copy the Private IPv4 address. You will paste it into the Universal Forwarder setup script.

Step 3 — Add User Data

Scroll to Advanced details. Paste the script below into the User data field before launching. Replace the two placeholder values first.

  • Replace PASTE-SPLUNK-SERVER-PRIVATE-IP-HERE with the private IP of the Splunk server.
  • Replace PASTE-YOUR-UNIVERSAL-FORWARDER-DEB-URL-HERE with your Universal Forwarder Linux .deb download URL.
bash — EC2 User Data for webserver-forwarder
#!/bin/bash
set -e

# Replace this with the private IPv4 address of your Splunk server.
SPLUNK_IP="PASTE-SPLUNK-SERVER-PRIVATE-IP-HERE"

# Paste your Splunk Universal Forwarder .deb download URL from splunk.com below.
UF_DEB_URL="PASTE-YOUR-UNIVERSAL-FORWARDER-DEB-URL-HERE"
UF_PASS="Forwarder2026!"

apt-get update -y
apt-get install -y apache2 php libapache2-mod-php wget curl

systemctl enable apache2
systemctl start apache2

cat > /var/www/html/index.html <<'EOF'
<!doctype html>
<html>
<head><title>Teacher Workshop Web Server</title></head>
<body>
  <h1>Teacher Workshop Web Server</h1>
  <p>This page creates a normal Apache access log entry.</p>
  <p><a href="/about.html">About</a> | <a href="/resources.html">Resources</a> | <a href="/login.php?user=teacher">Practice login page</a></p>
</body>
</html>
EOF

cat > /var/www/html/about.html <<'EOF'
<!doctype html>
<html>
<head><title>About</title></head>
<body><h1>About this lab</h1><p>This safe page is used to generate normal web logs.</p></body>
</html>
EOF

cat > /var/www/html/resources.html <<'EOF'
<!doctype html>
<html>
<head><title>Resources</title></head>
<body><h1>Resources</h1><p>Visit this page a few times to create simple page-view logs.</p></body>
</html>
EOF

cat > /var/www/html/login.php <<'EOF'
<?php
$user = preg_replace('/[^A-Za-z0-9_.-]/', '', $_GET['user'] ?? 'guest');
$time = date('Y-m-d H:i:s');
$line = "$time event=login user=$user outcome=practice_page_visit\n";
file_put_contents('/var/log/simple-login.log', $line, FILE_APPEND);
?>
<!doctype html>
<html>
<head><title>Practice Login</title></head>
<body>
  <h1>Practice Login Page</h1>
  <p>A safe practice login event was written for user: <strong><?php echo htmlspecialchars($user); ?></strong></p>
  <p>Try another example: <a href="/login.php?user=student1">student1</a></p>
</body>
</html>
EOF

touch /var/log/apache2/access.log /var/log/apache2/error.log /var/log/simple-login.log
chmod 644 /var/log/apache2/access.log /var/log/apache2/error.log /var/log/simple-login.log

# Generate a few starter events so learners see data quickly.
curl -s http://127.0.0.1/ > /dev/null
curl -s http://127.0.0.1/about.html > /dev/null
curl -s http://127.0.0.1/resources.html > /dev/null
curl -s http://127.0.0.1/login.php?user=teacher > /dev/null

wget -O /tmp/splunkforwarder.deb "$UF_DEB_URL"
dpkg -i /tmp/splunkforwarder.deb

/opt/splunkforwarder/bin/splunk start \
  --accept-license --answer-yes --no-prompt \
  --seed-passwd "$UF_PASS"

mkdir -p /opt/splunkforwarder/etc/system/local

cat > /opt/splunkforwarder/etc/system/local/outputs.conf <<EOF
[tcpout]
defaultGroup = splunk_indexer

[tcpout:splunk_indexer]
server = ${SPLUNK_IP}:9997
EOF

cat > /opt/splunkforwarder/etc/system/local/inputs.conf <<'EOF'
[monitor:///var/log/apache2/access.log]
index = webserverlogs
sourcetype = access_combined

[monitor:///var/log/apache2/error.log]
index = webserverlogs
sourcetype = apache_error

[monitor:///var/log/simple-login.log]
index = securitylogs
sourcetype = simple_login
EOF

/opt/splunkforwarder/bin/splunk restart
/opt/splunkforwarder/bin/splunk enable boot-start \
  --accept-license --answer-yes --no-prompt

Verify log collection

Now confirm the full data path: logs are generated on the web server, forwarded by the Universal Forwarder, received by Splunk, and searched in Splunk Search & Reporting.

Step 1 — Check the forwarder locally

Connect to the web server using EC2 Instance Connect and run:

bash — on the webserver-forwarder instance
sudo /opt/splunkforwarder/bin/splunk list forward-server -auth admin:Forwarder2026!
sudo /opt/splunkforwarder/bin/splunk list monitor -auth admin:Forwarder2026!
sudo tail -20 /var/log/simple-login.log

Step 2 — Search for web logs in Splunk

Open Splunk Web. Click Search & Reporting. Set the time range to Last 60 minutes. Run this search:

SPL
index=webserverlogs

Expected result: You should see Apache page visit events. These events came from /var/log/apache2/access.log.

Step 3 — Confirm the Apache access sourcetype

Run this search to confirm that Apache page visits are indexed with the standard Apache sourcetype.

SPL — confirm Apache access sourcetype
index=webserverlogs source="/var/log/apache2/access.log" | stats count by sourcetype

Expected result: The table should show access_combined. This confirms that Apache access logs are being collected from the web server and stored with the correct sourcetype.

Step 4 — Search for practice login logs

Run this search:

SPL
index=securitylogs

Expected result: You should see safe practice events such as event=login user=teacher outcome=practice_page_visit.

09

Simple SPL examples

SPL means Search Processing Language. It is the language used to search data in Splunk. Start simple. Run one search at a time in Search & Reporting.

How to run each search
  1. Open Search & Reporting.
  2. Paste the SPL into the search bar.
  3. Select Last 60 minutes or All time.
  4. Click the search icon or press Enter.
  5. Read the events or table results.

Query 1 — Show web server logs

SPL
index=webserverlogs
PartPlain meaning
indexAn index is a storage area in Splunk.
webserverlogsThis is where Apache web logs are stored.

Expected result: A list of web page visits. Learners can click an event to inspect fields such as time, host, source, and sourcetype.

Query 2 — Show practice login and user activity logs

SPL
index=securitylogs
PartPlain meaning
indexSearch inside one Splunk storage area.
securitylogsThis index stores the safe practice login log.

Expected result: Events containing simple text such as event=login user=teacher.

Query 3 — Count events by sourcetype

SPL
index=webserverlogs | stats count by sourcetype
PartPlain meaning
index=webserverlogsStart with web server events.
|The pipe sends results to the next command.
stats count by sourcetypeCount how many events belong to each log type.

Expected result: A table showing counts for sourcetypes such as access_combined and apache_error.

Query 4 — Find top pages visited

SPL
index=webserverlogs sourcetype=access_combined | top uri_path
PartPlain meaning
sourcetype=access_combinedOnly use normal Apache access log events.
top uri_pathShow the most common web page paths.

Expected result: A table with pages such as /, /about.html, /resources.html, and /login.php.

Query 5 — Show events over time

SPL
index=webserverlogs | timechart count
PartPlain meaning
timechartCreate a time-based chart.
countCount events in each time period.

Expected result: A line chart that rises when learners visit pages.

Query 6 — Search for the word login

SPL
index=securitylogs | search login
PartPlain meaning
index=securitylogsStart with the practice login log data.
| search loginKeep only events that contain the word login.

Expected result: A focused list of login practice events.

Query 7 — Count activity by user

SPL
index=securitylogs | stats count by user
PartPlain meaning
stats countCount how many events were found.
by userGroup the count for each user value.

Expected result: A table showing users such as teacher and student1, with a count beside each one.

10

Monitor Splunk Enterprise VM login activity

This activity teaches learners how to monitor login-related events on the Splunk Enterprise VM itself. The goal is defensive monitoring: learners look for successful login events and failed password events in Linux authentication logs.

General monitoring scenario

This activity uses Splunk to review login-related records from the Splunk Enterprise VM. It checks normal admin sign-ins, password failures, and repeated failures for the same username. Clearly labelled training events are created with the Linux logger command. These events are written to /var/log/auth.log, then Splunk indexes them.

Step 1 — Confirm Splunk is monitoring the local auth log

Open Search & Reporting. Set the time range to Last 60 minutes. Run this search:

SPL
index=securitylogs sourcetype=linux_secure
PartPlain meaning
index=securitylogsLook inside the security log index created earlier.
sourcetype=linux_secureShow only Linux authentication log events from /var/log/auth.log.

Expected result: You may see Linux session messages such as session opened, session closed, or other authentication-related system events. If there are no results yet, continue to Step 2.

Step 2 — Generate safe training login events

Connect to the splunk-server EC2 instance using EC2 Instance Connect. Run the commands below. They create safe, labelled training events. They do not attempt to sign in to any account.

bash — on the Splunk Enterprise VM
sudo logger -p authpriv.notice "login_monitor event=login user=teacher result=success source=splunk-enterprise-vm"
sudo logger -p authpriv.warn "login_monitor event=login user=student1 result=failure source=splunk-enterprise-vm reason=incorrect_password"
sudo logger -p authpriv.warn "login_monitor event=login user=student1 result=failure source=splunk-enterprise-vm reason=incorrect_password"
sudo logger -p authpriv.warn "login_monitor event=login user=student2 result=failure source=splunk-enterprise-vm reason=incorrect_password"
What these commands do

logger writes a message to the Linux system log. The authpriv facility places the message in the authentication log area. The text login_monitor is a marker that makes the training events easy to find in Splunk.

Step 3 — Search all training login events

Return to Splunk Web and run:

SPL
index=securitylogs sourcetype=linux_secure login_monitor
PartPlain meaning
login_monitorFind only the safe training login events created by the logger command.

Expected result: You should see one success event for teacher and three failure events for student1 and student2.

Search failed password events

SPL
index=securitylogs sourcetype=linux_secure login_monitor result=failure
PartPlain meaning
result=failureShow only the training events where the login result was a password failure.

Expected result: Three rows should appear. Two are for student1 and one is for student2.

Search successful login events

SPL
index=securitylogs sourcetype=linux_secure login_monitor result=success
PartPlain meaning
result=successShow only the training events where the login result was successful.

Expected result: One row should appear for teacher.

Count login activity by user

SPL
index=securitylogs sourcetype=linux_secure login_monitor | stats count by user
PartPlain meaning
| stats count by userCount how many login-monitoring events belong to each user.

Expected result: A table showing student1 with the highest count, then teacher and student2.

Count login activity by result

SPL
index=securitylogs sourcetype=linux_secure login_monitor | stats count by result
PartPlain meaning
by resultGroup the count into success and failure categories.

Expected result: A small table with failure count 3 and success count 1.

Step 4 — Search real Linux authentication text, if available

Some learners may also see normal Linux messages created by EC2 Instance Connect or system services. These searches help locate real authentication wording when it exists.

SPL — failed password text
index=securitylogs sourcetype=linux_secure "Failed password"
SPL — successful session text
index=securitylogs sourcetype=linux_secure ("Accepted password" OR "Accepted publickey" OR "session opened")

Expected result: Results depend on the Linux image and the way the session was opened. The safe login_monitor events above are more reliable for classroom teaching because every learner can reproduce them.

Build the dashboard

The dashboard gives learners a simple visual summary of the log data. Build it after the searches work, including the Splunk Enterprise VM login-monitoring activity.

Create the dashboard shell

  1. Open Search & Reporting.
  2. Run the first panel search below.
  3. Click Save As → Dashboard Panel.
  4. Choose New dashboard.
  5. Name it Beginner Log Analysis Dashboard.
  6. Choose a simple layout option such as Classic Dashboard if prompted.
  7. Save the panel.

Panel 1 — Total events

This panel shows the total number of events received from the web server and practice login log.

SPL
index=webserverlogs OR index=securitylogs | stats count as "Total Events"

Visualisation: Single Value.

Panel 2 — Events over time

This panel shows when events arrived. It helps learners connect page visits with visible changes in Splunk.

SPL
index=webserverlogs OR index=securitylogs | timechart count

Visualisation: Line Chart.

Panel 3 — Top pages visited

This panel shows which web pages were visited most often.

SPL
index=webserverlogs sourcetype=access_combined | top uri_path

Visualisation: Bar Chart or Table.

Panel 4 — Login practice activity

This panel shows how many safe login practice events were created for each user.

SPL
index=securitylogs sourcetype=simple_login | stats count by user

Visualisation: Column Chart or Table.

Panel 5 — Splunk VM login results

This panel shows success and password failure training events from the Splunk Enterprise VM.

SPL
index=securitylogs sourcetype=linux_secure login_monitor | stats count by result

Visualisation: Pie Chart, Column Chart, or Table.

How to add the remaining panels

  1. Run the next search in Search & Reporting.
  2. Open the Visualisation tab and select the suggested visualisation.
  3. Click Save As → Dashboard Panel.
  4. Choose Existing dashboard.
  5. Select Beginner Log Analysis Dashboard.
  6. Give the panel a clear title.
  7. Click Save.

Suggested layout

  • Place Total events at the top.
  • Place Events over time below it as a wide chart.
  • Place Top pages visited and Login practice activity side by side.
  • Place Splunk VM login results under the login activity panel or beside it if there is enough space.
  • Use simple panel names and avoid too many colours.
Expected result

Learners can refresh the dashboard, visit the web pages again, and see the panels update with new events.

Practice exercises

Use these short activities to check understanding.

  1. Visit /about.html three times, then run index=webserverlogs | timechart count. What changed?
  2. Visit /resources.html two times, then run index=webserverlogs sourcetype=access_combined | top uri_path. Which page is now near the top?
  3. Open /login.php?user=teacher and /login.php?user=student1, then run index=securitylogs | stats count by user. Which users appear?
  4. Run index=webserverlogs | stats count by sourcetype. What log types are shown?
  5. Run index=securitylogs sourcetype=linux_secure login_monitor | stats count by result. How many success and failure events appear?
  6. Explain the data journey in one sentence: server → log file → Splunk index → search → dashboard.

Splunk Academy and certification introduction

This final section connects the workshop to official Splunk learning pathways. The workshop gives a practical starting point. Splunk Academy, Splunk Education, and Splunk Certification provide the next structured steps for learners who want to continue.

What is Splunk Academy?

Splunk Academy is the learning and training pathway connected to Splunk Education. It includes self-paced learning, official course catalogues, learning paths, and certification preparation. For a classroom setting, it is useful because students can continue practising after the workshop using official materials.

Recommended learning pathway after this workshop

StageFocusGood next step
1. Beginner userSearching, fields, events, reports, and dashboards.Complete free introductory Splunk training and repeat the searches from this workshop.
2. Core userUse SPL confidently, understand fields, save reports, and create basic alerts and dashboards.Prepare for Splunk Core Certified User.
3. Power userBuild stronger searches and use knowledge objects such as field aliases, event types, macros, and data models.Prepare for Splunk Core Certified Power User.
4. AdministratorManage Splunk Enterprise, users, indexes, forwarders, inputs, and platform health.Prepare for Splunk Enterprise Certified Admin after meeting the required prerequisite.

Beginner-friendly certification overview

CertificationWho it suitsPlain-language description
Splunk Core Certified UserNew Splunk users and students after an introductory lab.Shows that a learner understands Splunk basics such as searching, fields, lookups, alerts, basic statistical reports, and dashboards.
Splunk Core Certified Power UserLearners who already understand basic searching and want stronger reporting skills.Shows broader skill with SPL, reports, dashboards, field knowledge, event types, macros, workflow actions, and data models.
Splunk Enterprise Certified AdminTechnical staff who manage Splunk Enterprise environments.Shows administration skill, including data inputs, forwarders, users, indexes, configuration, and daily platform management. Splunk lists Splunk Core Certified Power User as a prerequisite.
Splunk Cloud Certified AdminTeams using Splunk Cloud rather than self-managed Splunk Enterprise.Focuses on daily Splunk Cloud administration, data inputs, forwarders, user accounts, and troubleshooting.
Certification details can change

Exam names, prerequisites, prices, and registration processes may change. Always check the official Splunk Certification pages before advising students or planning assessment pathways.

Useful official links

How to introduce certification in class

  1. Start with the practical skills from this workshop: indexes, sourcetypes, searches, reports, and dashboards.
  2. Explain that certification is optional, but useful for students who want evidence of Splunk skills.
  3. Present Splunk Core Certified User as the most suitable first target after introductory practice.
  4. Present Splunk Core Certified Power User as the next step for students who want deeper SPL and reporting skills.
  5. Present Splunk Enterprise Certified Admin as a later pathway for students interested in system administration, platform management, or SOC infrastructure roles.
